Three instruments covering the biological admissibility domain of the UNNS Substrate Program. STRUC-BIO-II and STRUC-BIO-I form a strict two-stage pipeline: STRUC-BIO-II compiles raw fitness landscape data (QT45 direct measurements, FASTA pool sequencing, or quasispecies modelling) into structured mutation files, which STRUC-BIO-I then ingests to evaluate the UNNS admissibility inequality on epistasis graphs: ρ = inv/ν ≤ 1. STRUC-I v1.0.4 operates independently: it applies the universal κ-step ladder protocol directly to the pre-compiled CSV ladders from the FOR_STRUC-I_CHAMBER_DATA folder, certifying structural admissibility across any ordered property sequence.

📋 Pipeline Guide — How to Run STRUC-BIO-II → STRUC-BIO-I → STRUC-I

Overview

This pipeline connects three instruments in a strict left-to-right data flow. STRUC-BIO-II is the entry point: it accepts raw biological data in one of three modes and compiles it into normalised mutation files. Those files feed directly into STRUC-BIO-I, which evaluates the UNNS admissibility inequality on the double-mutant epistasis graph. STRUC-I v1.0.4 then applies the general κ-step ladder protocol to any ordered property CSV you supply — including ladders derived from the biological compilation.

Stage 1 — STRUC-BIO-II: Biological Structure Compiler

STRUC-BIO-II accepts three independent input modes. Choose the one matching your data source. All modes produce the same output format consumed by STRUC-BIO-I.

Mode A — QT45 (direct fitness measurements)

Input files (from QT45 MODE folder in the zip) Use when you have experimentally measured single- and double-mutant fitness values.
  1. Drop data_QT45_v2_singlemut_fitnes.txt — tab-separated LABEL FITNESS rows (no header required).
  2. Drop data_QT45_v2_doublemut_fitnes.txt — tab-separated LABEL_A LABEL_B FITNESS rows.
  3. Optionally drop a WT FASTA. If omitted, the hardcoded 45-nt QT45 master sequence is used automatically.
  4. Click COMPILE. The compiler validates labels, resolves strand orientation, and writes the output panel.
  5. Click EXPORT FOR STRUC-BIO-I to download wildtype.json, singles.csv, and doubles.csv.

Mode B — FASTA POOL (sequencing pool fitness inference)

Input files (from FASTA POOL MODE folder in the zip) Use when fitness values are inferred from enrichment ratios between FL and IP sequencing pools.
  1. Provide the WT sequence — drop a FASTA file or paste directly. RNA (U) is auto-converted to DNA (T).
  2. Drop the *_FL.fasta (full-length reads pool) and *_IP.fasta (in-progress / selected reads pool).
  3. Click COMPILE. Sequences are classified: 0 mutations → WT bucket; 1 → singles; 2 → doubles; 3+ → ignored (counted in diagnostics). All output is tagged source: estimated.
  4. Click EXPORT FOR STRUC-BIO-I to download the three output files.

Mode C — QUASISPECIES (error-threshold / fidelity modelling)

Input files (from QUASISPECIES MODE folder in the zip) Use when you want to model the fitness landscape via mutation–selection matrices at varying fidelity.
  1. Drop the master_sequence.fasta WT reference. RNA is auto-converted to DNA.
  2. Provide the fidelity value(s) to model.
  3. Strongly recommended: also drop empirical singles and doubles (e.g. the QT45 measured files). Without these, uniform matrices produce a flat landscape — C=0 is guaranteed and the result is structurally uninformative.
  4. In hybrid mode: f_combined = f_measured + F̂(fidelity) where F̂ = log₂P(mut|wt,f) − log₂P(wt|wt,f). Doubles use measured epistasis plus fidelity-shifted singles.
  5. Click COMPILE, then EXPORT FOR STRUC-BIO-I.
STRUC-BIO-II output Three files are produced regardless of mode: wildtype.json — WT sequence and metadata; singles.csv — single-mutant fitness table; doubles.csv — double-mutant fitness table. Hamming-0 entries are stripped automatically. These files are the direct input to Stage 2.

Stage 2 — STRUC-BIO-I: Epistasis Graph Structural Analysis

STRUC-BIO-I evaluates the UNNS admissibility inequality on the double-mutant epistasis graph: ρ = inv / ν ≤ 1, where inv is the inversion count under κ-step perturbation and ν is the vulnerability capacity derived from the gap spectrum.

  1. Drop singles.csv from Stage 1 output.
  2. Drop doubles.csv from Stage 1 output.
  3. Optionally drop wildtype.json to annotate the report with WT metadata.
  4. Configure parameters: dataset ID, κ-step grid, Monte Carlo runs, max-ladder cap.
  5. Click RUN. The chamber evaluates the epistasis graph across the full κ-grid, computing ρ for each node pair and checking the admissibility bound.
  6. Inspect the live results panel. Key indicators: D (degree count), C (candidate edges), ρ (max observed), z-score vs. null.
  7. Click EXPORT JSON to download the full result bundle, or EXPORT REPORT for the annotated HTML report. The JSON bundle is the reference input for corpus-level analysis.
Interpreting the STRUC-BIO-I result ρ ≤ 1 across all evaluated pairs = admissible — the epistasis graph satisfies the USL bound. ρ > 1 for any pair = violation — a genuine falsifier event requiring investigation. The z-score measures the margin above the random-graph null: high positive z indicates strong structural evidence beyond chance. The QT45 reference result: D=72, C=2,235, ρ=0.0322, z=+4.22 — clean admission.

Stage 3 — STRUC-I v1.0.4: Universal Ladder Admissibility

STRUC-I v1.0.4 operates independently of the STRUC-BIO-II → STRUC-BIO-I pipeline. It applies the general κ-step ladder protocol to pre-compiled ordered property CSV files. Its biological-domain input comes directly from the FOR_STRUC-I_CHAMBER_DATA folder in the input bundle — not from STRUC-BIO-I output. Load those CSV ladders into STRUC-I directly.

  1. Open STRUC-I. The chamber supports up to 6 CSV files simultaneously.
  2. Drop one or more CSV ladder files from the FOR_STRUC-I_CHAMBER_DATA folder (e.g. band_gap_ladder.csv, density_ladder.csv, formation_energy_ladder.csv). Schema is auto-detected.
  3. Set parameters: dataset family/class labels, max-ladder cap, MC runs, κ-step count and range (κ_min, κ_max).
  4. Click RUN. For each ladder, STRUC-I evaluates the admissibility bound across the full κ-grid. The percolation threshold κ* ≈ 0.554102 is the key structural landmark.
  5. Inspect the per-ladder regime classification: Stable Structure, Weak Persistence, Boundary-Stabilized, or Random Structure.
  6. Click EXPORT JSON or EXPORT CSV to download the full result bundle for manuscript integration.
STRUC-I v1.0.4 validated corpus result Across 3,073 physical ladders spanning 13 domains: zero violations across all 240 κ-step evaluations. This corpus result is the empirical backbone of the USL manuscript. The FOR_STRUC-I_CHAMBER_DATA folder provides pre-compiled CSV ladders for direct ingestion — independent of the STRUC-BIO-II → STRUC-BIO-I data flow.

▸ PIPELINE PROTOCOL

  • Falsification-first: all three chambers are explicitly designed as falsification engines. ρ > 1 is a genuine violation — reported accurately, never softened.
  • Null results as structural findings: zero violations across the full κ-grid carry as much evidential weight as positive detections. Absence of violation is positive structural evidence.
  • Data integrity: manuscript numbers are locked to chamber JSON exports. Any discrepancy between documentation and instrument output is treated as a bug requiring correction.
  • Admissibility ≠ realizability: structural admissibility (satisfying ρ ≤ 1) does not imply realizability or compositional benefit — this distinction is maintained throughout.
  • Input files: all input files required by every mode are bundled at input_files.zip.
  • Regime taxonomy: classification states (Stable Structure, Weak Persistence, Boundary-Stabilized, Random Structure) are consistent across all STRUC-I evaluations.
