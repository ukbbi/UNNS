# input_files

Input data bundle for the UNNS biological admissibility extension.

This folder contains the chamber-ready source inputs for the biological pipeline:

- `QT45 MODE`
- `FASTA POOL MODE`
- `QUASISPECIES MODE`
- `FOR_STRUC-I_CHAMBER_DATA`

These four subfolders correspond to the input branches described by the UNNS Biological Pipeline array. `STRUC-BIO-II` consumes the first three modes and compiles them into structured mutation outputs, while `STRUC-I v1.0.4` consumes the precompiled CSV ladders from `FOR_STRUC-I_CHAMBER_DATA` directly. 

---

## Purpose

This directory serves as the reproducibility and ingestion pack for the biological admissibility extension of the Universal Structural Law workflow.

It provides:

- raw or semi-raw biological inputs for `STRUC-BIO-II`
- precompiled ladder CSVs for `STRUC-I v1.0.4`
- a clean separation between compilation-stage data and direct ladder-analysis data
- a single bundled source for all chamber runs in the biological corpus package 

---

## Folder structure

### `QT45 MODE/`
Input files for direct fitness compilation from the QT45 ribozyme landscape.

Use this folder when running `STRUC-BIO-II` in **QT45 mode**.

Expected role:

- measured single-mutant fitness inputs
- measured double-mutant fitness inputs
- optional wildtype FASTA reference

Pipeline function:

- source for direct experimentally measured fitness compilation
- upstream input to `STRUC-BIO-II`
- produces:
  - `wildtype.json`
  - `singles.csv`
  - `doubles.csv` 

Typical files described by the chamber guide:

- `data_QT45_v2_singlemut_fitnes.txt`
- `data_QT45_v2_doublemut_fitnes.txt`
- optional WT FASTA file 

---

### `FASTA POOL MODE/`
Input files for sequence-pool-based biological fitness inference.

Use this folder when running `STRUC-BIO-II` in **FASTA POOL mode**.

Expected role:

- full-length sequencing pool FASTA
- selected / in-progress sequencing pool FASTA
- wildtype sequence reference

Pipeline function:

- source for inferred fitness estimation from enrichment ratios
- upstream input to `STRUC-BIO-II`
- sequences are bucketed by mutation count:
  - 0 mutations → WT
  - 1 mutation → singles
  - 2 mutations → doubles
  - 3+ mutations → ignored in structural compilation 

Typical files described by the chamber guide:

- `*_FL.fasta`
- `*_IP.fasta`
- WT FASTA or pasted WT sequence 

---

### `QUASISPECIES MODE/`
Input files for mutation–selection / fidelity modelling.

Use this folder when running `STRUC-BIO-II` in **QUASISPECIES mode**.

Expected role:

- master sequence FASTA
- fidelity-controlled modelling inputs
- optional empirical mutation fitness files for hybrid runs

Pipeline function:

- source for theoretical or hybrid biological landscape construction
- upstream input to `STRUC-BIO-II`
- supports fidelity-dependent compilation of mutation fitness structure
- recommended for use together with empirical singles/doubles data to avoid flat uninformative landscapes 

Typical files described by the chamber guide:

- `master_sequence.fasta`
- fidelity parameter inputs
- optional empirical singles and doubles files 

---

### `FOR_STRUC-I_CHAMBER_DATA/`
Precompiled ordered-property ladder CSVs for direct `STRUC-I v1.0.4` ingestion.

This folder is **not** part of the `STRUC-BIO-II → STRUC-BIO-I` compilation chain.

Use this folder when running `STRUC-I v1.0.4` directly.

Pipeline function:

- direct ladder input for universal admissibility testing
- independent from the biological compilation outputs
- used for κ-step ladder evaluation and regime classification 

Typical examples named in the chamber guide:

- `band_gap_ladder.csv`
- `density_ladder.csv`
- `formation_energy_ladder.csv`

## Consumption map

### `STRUC-BIO-II` consumes
- `QT45 MODE/`
- `FASTA POOL MODE/`
- `QUASISPECIES MODE/`

Output from `STRUC-BIO-II`:
- `wildtype.json`
- `singles.csv`
- `doubles.csv` 

### `STRUC-BIO-I` consumes
- `singles.csv`
- `doubles.csv`
- optional `wildtype.json`

These are generated by `STRUC-BIO-II`, not stored as a primary branch in this folder. 

### `STRUC-I v1.0.4` consumes
- ladder CSVs from `FOR_STRUC-I_CHAMBER_DATA/`

This path is independent of `STRUC-BIO-I`. `STRUC-I` does not consume `STRUC-BIO-I` output. 

---

## Operational distinction

This folder intentionally separates two different kinds of chamber inputs:

### Compilation inputs
Used by `STRUC-BIO-II`:
- `QT45 MODE/`
- `FASTA POOL MODE/`
- `QUASISPECIES MODE/`

These are transformed into standardized mutation tables.

### Direct ladder inputs
Used by `STRUC-I v1.0.4`:
- `FOR_STRUC-I_CHAMBER_DATA/`

These are already in ladder form and are loaded into the universal chamber without biological recompilation.
