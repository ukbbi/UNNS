# ADAPTER SPECIFICATION v0.1

## Status

**FROZEN BEFORE FIRST CHAMBER RUN**

This specification defines the primary ladder used in the first
`UNNS_TRACEABILITY_PHENOTYPE` experiment.

No STRUC-I or STRUC-PERC-I result was inspected before this specification was frozen.

## 1. Primary experimental object

The first chamber experiment uses one primary ladder per algebraic system:

`SYSTEM_SPECTRUM`

The spectrum is generated from the admissible elements of the system itself.
It does **not** use the exact refinement witness, the failure witness, or the
ground-truth label when constructing the ladder.

This is deliberate. The primary question is whether the structural chambers can
detect a secondary phenotype of traceability from the system's admissible state
geometry without being handed the answer through a witness encoding.

Route-specific objects (`route_ab`, `route_cd`, `refinement`, `failure_witness`)
are reserved for a later secondary analysis after the primary chamber outputs are frozen.

## 2. Common construction

For every case, regard the system as a finitely generated additive monoid after
the domain-appropriate logarithmic/additive representation.

Let the generator heights be positive real numbers `h_1,...,h_s`.

Enumerate distinct monoid elements in increasing generator word depth, beginning
with the zero element.

For each exact monoid element `x`, compute a scalar height `H(x)`.

Retain the first:

`N = 128`

distinct monoid elements in ascending scalar height.

The enumeration continues beyond the first point at which 128 elements exist
until completeness of the retained prefix is certified:

`(D + 1) * h_min > H_128`

where:

- `D` is the maximum generator word depth already enumerated;
- `h_min` is the smallest generator height;
- `H_128` is the 128th retained height.

Because every unseen element has word depth at least `D+1`, this inequality
guarantees that no unseen element can enter below the retained 128th level.

The zero element is retained as the first ladder value.

## 3. Domain adapters

### 3.1 `INT_FREE`

The active positive-integer factorization monoid is represented additively by
prime exponents.

For active primes `p_1,...,p_r`:

`H(alpha) = sum_i alpha_i * log(p_i)`.

This is the same logarithmic prime-valuation geometry used by the parent
Phase-1 work, now applied to the bounded system spectrum rather than to one
individual integer.

No additional normalization is applied.

### 3.2 `R1_FREE` and `R1_FAIL`

For a rank-one additive monoid generated by positive integers:

`H(x) = x`.

The exact monoid element is the integer itself.

### 3.3 `AFF_FREE` and `AFF_FAIL`

For an affine monoid in nonnegative integer coordinates:

`x = (x_1,...,x_d)`,

use the fixed positive projection:

`H(x) = x_1*sqrt(2) + x_2*sqrt(3) + x_3*sqrt(5) + ...`

using the first `d` square roots of distinct primes.

This projection is fixed across positive and negative affine classes and does
not depend on the label.

For the dimensions used in the preregistered corpus, it is injective on the
integer lattice because the selected square-root basis is rationally independent.

## 4. Deduplication rule

Deduplication is performed on the **exact algebraic monoid element before scalar
projection**, not by floating-point proximity.

This means relation-induced collisions in a nonfree monoid are retained as a
genuine reduction in the number and placement of admissible states rather than
being counted as separate factorization words.

No post-projection tolerance is used by the project adapter.

## 5. Scale policy

The project does not rescale the ladders.

This is intentional because both frozen chambers define their perturbation /
connectivity scales from internal robust gap statistics:

- STRUC-I uses `epsilon = kappa * median(gaps)`;
- STRUC-PERC-I uses its internal median/IQR gap scale.

The raw system geometry is therefore supplied unchanged.

## 6. Chamber input files

STRUC-I:

`inputs/struc_i/ALL_SYSTEM_SPECTRA.csv`

Schema:

`case_id,value`

The chamber recognizes `case_id` as a grouping column and produces one ladder
per case in a single upload slot.

STRUC-PERC-I:

`inputs/struc_perc_i/<CASE_ID>.csv`

Schema:

`value`

These 30 files are intended for the chamber's batch mode.

## 7. Ground-truth isolation

Ground-truth labels live in:

`corpus/CORPUS_INDEX.csv`

The ladder builder never branches on `TRACEABLE` versus `NON_TRACEABLE`.

The label is used only during downstream synthesis after both raw chamber result
sets have been retained.

## 8. Primary observables

The first synthesis will read the chamber-native observables only.

STRUC-I primary fields:

- regime/state;
- mean `A_k`;
- minimum `A_k`;
- mean rho;
- maximum rho.

STRUC-PERC-I primary fields:

- verdict tier;
- giant ratio;
- `kappa_connect` when present;
- isolated fraction;
- tail dominance.

No new composite score is preregistered for the first run.

## 9. Primary comparison

The first comparison is descriptive and cross-domain:

- TRACEABLE versus NON_TRACEABLE;
- rank-one failures versus higher-rank affine failures;
- within-class spread;
- consistency of effect direction across domain families;
- explicit cases where the chambers do not separate the labels.

The initial corpus is structural and deliberately small. It is **not** to be
treated as an iid sample for classical significance testing.

## 10. Freeze rule

Any change to:

- `N=128`;
- the projection weights;
- exact-element deduplication;
- the five corpus classes;
- the selected 30 systems;
- chamber code;

requires a separately versioned experiment.
