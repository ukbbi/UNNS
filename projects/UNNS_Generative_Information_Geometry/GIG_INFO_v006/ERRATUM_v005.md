# Erratum — GIG-INFO v005 parent identification
**Defect.** In v005 `ENGINE/_vpath.py` a global substitution (v004→v005) rewrote the *first* occurrence on the `NAMES` line, so key `V004` pointed at `GIG_I_v005` instead of `GIG_I_v004`. Consequences: (i) `MANIFEST.json` of v005 lists the same parent hash for V004 and V005 (aea157c8…); the true GIG-I v004 manifest hash is 26e14d97…; (ii) the GIG-I v004 ENGINE folder was not on `sys.path` while GIG-I v005 appeared twice.
**Impact assessment (done in v006).** A copy of the v005 package with the one-token fix was re-tested: all mathematical tests pass (10/11; the only failure is the manifest hash of the edited `_vpath.py`, as expected), and `A22_pair_anatomy.json` regenerated identically. No v005 result, certificate or theorem depends on a GIG-I v004-only module. The 46 v005 file hashes remain self-consistent.
**Fix.** v006 `_vpath.py` maps all keys correctly; v006's MANIFEST records distinct parent hashes (GIG_I_v004 = 26e14d97…). v005 is left untouched (frozen); this erratum supersedes its parent table.
**Other parent hashes.** Parent manifests recorded in v006 are those of the folders present in the build workspace on 2026-11-06. If an earlier uploaded archive of a parent has a different manifest hash, the two are different builds of that parent; this cannot be resolved from inside the workspace and should be reconciled by comparing against the archives on the device.
